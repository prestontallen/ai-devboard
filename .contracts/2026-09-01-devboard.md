# Contract — Devboard: file-driven task dashboard

- **Date:** 2026-09-01
- **Tier:** 2 (Feature)
- **Status:** fulfilled (accepted 2026-09-01)
- **Worklog:** —

## Intent

Reading agent output in a terminal all day makes it hard for the human to
stay oriented. Devboard is a browser dashboard that renders the dev-context
workflow's state for the human: per-task plan, contract scorecard,
decisions, code-to-know, and a "needs you" attention queue. It is a **dumb
renderer over a file-drop protocol** — agents write one YAML/JSON file per
task into a shared directory (grouped by repo dir); a Docker container
mounts that directory read-only and serves the UI. The page hot-reloads
when files change; the human never presses refresh.

## Scope

**In:**
- `devboard/` in this repo: Dockerfile, compose file, server, single-page UI
- Server: Python 3.12 stdlib + PyYAML only; serves `index.html`,
  `/api/tasks`, and an SSE endpoint driven by a ~1s mtime scan
- UI: repo→task grid with phase badges and needs-you highlighting; task
  detail with plan todos, scorecard, decisions, code-to-know (syntax
  highlighted), needs-you, links; global attention queue
- Task file schema v1 (`schema: 1`), documented with an example file
- Read-only volume mount; unknown schema fields rendered generically

**Out (explicitly not doing):**
- Any write path from the UI (checking off todos, replying) — render only
- Auth, TLS, multi-user — localhost tool
- WORK.md/worklog rendering (v2 candidate)
- `devboard-update` helper script for agents (separate task; ties to
  wfs-canonize-scripts)
- dev-context/contract skill edits to mandate writing task files (separate
  follow-up task once the schema proves out)
- inotify/watchdog — mtime scan only

## Deliverables

- `devboard/Dockerfile`, `devboard/compose.yaml`
- `devboard/server.py`, `devboard/static/index.html`
- `devboard/schema.md` + `devboard/examples/<repo>/<task>.yaml`
- `devboard/README.md` (build/run one-liners)

## Constraints & assumptions

- Linux host, Docker with compose; port 8484 default (overridable via env)
- Latency target "within 2s" = 1s scan + client render; not hard realtime
- Assumes task files are written atomically (temp+rename) by producers;
  a torn read must still fail soft (error card), not crash the server

## Risks & open questions

- Schema drift agents↔renderer — mitigated by `schema: 1` + generic
  rendering of unknown fields
- Syntax highlighting without CDN (page should work offline): use a small
  vendored highlighter or regex-based minimal highlighting — **open:
  acceptable to keep highlighting minimal (keywords/strings/comments) in
  v1?** Assumed yes.
- Root dir default `~/.local/share/devboard` — **open: confirm location.**
  Assumed yes.
